# Object layout + naming crypto (Phase 4.5)

On-disk tree under `<prefix>/ic-v1/`:

| Relative path | Role |
|---------------|------|
| `vault.json` | Cleartext **version + KDF params + KDF salt**; wrapped DEK as base64 (`wrapDek` / strict parse) |
| `manifest.json.enc` | Encrypted manifest blob (AEAD) |
| `devices/<devH>.json.enc` | Per-device metadata |
| `log/<devH>/<seq:012d>.enc` | Append-only log segments |
| `snap/<epoch:08d>.enc` | Snapshots |
| `lock/<name>.lock` | Coarse locks |

**Naming:** `namingKey = HKDF-SHA256(DEK, info="ic-storage-names-v1")`; `devH = Crockford-base32(HMAC-SHA256(namingKey, canonical_lowercase_device_uuid)[0:16])`. **`devH`** must match `^[0-9A-HJKMNP-TV-Z]{26}$` in paths and AAD.

**Log segments:** AEAD envelope of JSON `{ dev, seq, prev_digest, created_at, mutations }` (no extra fields). **`prev_digest`** is empty at `seq === 0`; otherwise a **64-character lowercase hex** sha256 of the previous segment envelope. **AAD** = `ic-storage|v1|log|devH|seq` (versioned). Plaintext is **length-prefixed** (uint32 BE) JSON padded with zeros to one or more **4096-byte** buckets; padding tails must be all zero. **Decrypt** binds path **`seq`** and **`devH`** to the record (`deriveDevH(dek, dev)`). **Chain verify** requires an anchored **`expectedHead` `{ seq, digest }` from trusted, monotonic local state** (the last verified tip for that `devH`), contiguous segments `0..seq`, and matching **`prev_digest`** links (rejects truncation, rollback, gaps, forks). **Trust-on-first-use:** a device with no local trusted head for a remote `devH` accepts the first verified chain tip it sees; afterwards the trusted head only moves forward — a lower seq or digest mismatch at a known seq is a rollback/fork error (fail closed, never silently accept).

**Object keys** use **lowercase** `devH` path segments; crypto/AAD uses canonical uppercase Crockford `devH`. **No plaintext sync metadata** on remote storage — only sealed storage objects (including encrypted log segments).

**Local sync state** (vector cursor, trusted per-device `{seq,digest}` heads, ledger, conflicts, HLC clock) lives in **`~/.infinitecontext/object-store-sync-state.json`** (CLI) and **`daemon.db`** → `object_store_sync_state` (daemon). **`sync-cli-state.json` holds only the CLI pull cursor** — it must never embed object-store trust. Writes use **pid+random tmp**, **fsync+rename**, and a **`.lock` file** with `{ pid, hostname, createdAt, heartbeatAt }`: acquire retries ~10s with jitter; the holder refreshes **`heartbeatAt` every 15s**. A lock is **never broken** while its pid is alive on the same host. Stale break applies when the pid is dead on the same host, or heartbeat age exceeds **60s** (remote hosts). Empty/partial lock files get a short **5s** grace before break. Stale break is **atomic** (rename to a unique quarantine name, re-verify, then unlink). Orphan state tmp files matching **`*.tmp-<pid>-<hex>`** older than **10 minutes** are removed at CLI state startup. Stale lock quarantine files are dropped when the lock holder (or breaker) pid is dead; restoring a quarantined lock uses **`link()`** and never overwrites a lock recreated in the meantime. Saves merge under lock (max trusted heads + digest check, union ledger/conflicts). Corrupt state fails closed (`ObjectStoreSyncStateError`). After a segment is written, state save is **best-effort retried**; a failed save is recovered on the next run via remote `client_id` reconcile.

**CLI / daemon pull replicas:** object-store pull changes (`hlc` present) converge through shared **`applySyncChangeToReplica`** (`apps/js-sdk/lib/sync-replica-apply.mjs`). The CLI persists **`~/.infinitecontext/sync-replica.json`**; the daemon persists a single row in **`daemon.db`** → **`sync_replica_state`** (transactional upsert after each apply batch). **Hosted pull** (no `hlc`) is unchanged: **`sync_message_nodes`** / **`sync_context_meta`** with hard deletes. Replica JSON uses the same tmp rule as other local state files: **`*.${pid}.${hex}.tmp`** then rename.

**Pull routing (daemon / CLI):** hosted sync changes (no `hlc` / no `source_dev_h`) continue through the legacy **`sync_message_nodes`** / **`sync_context_meta`** path. Object-store transport changes (`hlc` plus non-empty **`source_dev_h`**) apply only when **`objectStoreReplicaPullEnabled`** is true. On hosted **`storage.backend`**, the daemon calls **`initObjectStoreReplica({ objectStoreBackend: false })`** so stray object-store-shaped rows route to the hosted SQLite path; local object-store backends use **`initObjectStoreReplica({ objectStoreBackend: true })`** (default). **`store.applySyncChange`** mirrors that flag. **`pullAndApplySync`** skips loading the JSON replica unless the flag is set. The engine applies object-store changes to the shared replica via **`applySyncChangeToReplica`**; hosted-shaped rows still use the SQLite meta tables. **`config doctor`** validates local replica JSON (CLI file and configured **`daemon.db`** row) even when the API is unreachable; JSON parse failures surface as **`corrupt_state`**.

**Compaction / manifest:** encrypted **`manifest.json.enc`** holds device rows (last/acknowledged seq plus optional acknowledged merge cursor), monotonic **`manifest_generation`**, **`compacted_through`**, **`latest_snapshot_epoch`**, and snapshot **trusted_heads** hints. **`snap/<epoch>.enc`** is create-only (CAS) and stores the sanitized replica, **`compacted_through`**, and per-device trusted tips so rollback/fork checks survive compaction. New devices bootstrap atomically from the verified snapshot at **`latest_snapshot_epoch`** (refuse when that object is missing or omits a manifest-known device): local state receives trusted heads plus a merge cursor covering every snapshot **`trusted_heads`** entry, and the pull response carries **`bootstrap_replica`**. **`pullAndApplySync`** (CLI and daemon) hydrates that replica, ignores hosted numeric **`since=0`** when the transport uses vector cursors, and calls **`confirmPullDelivery`** only after the replica flush commits. Manifest acks are capped to trusted heads and deferred until delivery is confirmed. **GC** deletes `log/<devH>/<seq>` only when **`seq` ≤ min(`compacted_through[devH]`, head−1)**, **`seq` is not the trusted head**, and every manifest device row has **`acknowledged_cursor[devH]`** (or own **`acknowledged_seq`**) through the floor; devices absent from the manifest block GC. Chain verify after GC anchors at trusted heads (not seq 0). Orphan snapshots after a crash are adopted or skipped by epoch listing before the next compaction. Shared manifest/snapshot writes use CAS read-modify-write (skip when unchanged), or **`lock/<name>.lock`** lease files when CAS is unavailable (advisory, 60 s TTL, fencing token on writes).

**Mutation log + compaction:** per-message history lives in **`_message_mutations`** (in-memory during pull; persisted in replica JSON). Each entry records coordinates (`devH`, `seq`, `index`), HLC, op, optional **`update_base_vector`** / **`delete_base_vector`**, and payload **`data`** only while needed to recompute conflicts. After each recompute, **`compactMutationLogForMessage`** keeps deletes, the current winner, and loser rows referenced by **`sync_conflicts`**; superseded plaintext that is causally covered by a later mutation is dropped from the log, and tombstoned **`messages`** entries drop live payload. On persist, **`sanitizeSyncReplicaForPersist`** strips log **`data`** that is no longer needed (superseded and covered, or on tombstoned messages), but **keeps `sync_conflicts` rows' `right_payload.data`** for **`tombstone_blocked_update`** so concurrent edits or re-appends that lost to a delete remain recoverable. The daemon SQLite store uses **`PRAGMA secure_delete=ON`** and a **`TRUNCATE`** WAL checkpoint after deletes so deleted plaintext does not land in the main database file. Corrupt mutation logs throw **`ObjectStoreSyncStateError`** (`corrupt_state`).

**Merge / replica (object store clients):** mutations carry an **HLC** `{ wall_ms, counter }` with **`devH` from the segment path**. Pull emits `hlc` plus `source_dev_h` / `source_seq` / `source_index`. When **`hlc` is present** (object-store sync), `applySyncChangeToReplica` applies **LWW by HLC** for appends/updates and **permanent delete tombstones**; displaced values emit conflicts keyed by **`messageId:loserDevH:loserSeq:loserIndex`** (kind is not part of the id). **`kind`** is **`tombstone_blocked_update`** when the message is tombstoned in the final replica, otherwise **`lww_superseded`**, recomputed from the mutation log so conflict sets match across pull order. **`message_update`** carries **`base_vector`** (snapshot at plan/push time); an update whose base covers the prior winner source is treated as **sequential** and does **not** create an `lww_superseded` row. **`message_delete`** uses **`base_vector`** to decide whether a delete displaces a concurrent winner (uncovered winner → conflict). Plain deletes with nothing to displace emit no conflict record. **Hosted sync** (changes without `hlc`) keeps **main** behavior: deletes remove message entries (no tombstones, no object-store conflict ledger). Remote segment HLC **> now + 5min** is not applied: pull returns **`clock_skew`** for that `devH` (with **`resume_at_ms = wall_ms - 5min`**); once local time reaches that point, pull resumes. Local HLC clock still caps at **now + 5min**.

**Delete stale-base (object store transport):** `message_delete` requires explicit **`base_vector`** (snapshot at plan time, carried through the outbox). Push checks stale against **`base_vector` only** (not the live cursor), scanning **every `devH` under `log/`** on remote storage. A device missing from `base_vector` is treated as **seq -1** (so remote **seq 0** is uncovered). Conflicts are deterministic (`delete_stale_base:…`).

**Owner push:** before every push, re-verify the trusted anchor and prefix; fail closed on rollback/fork. Pull checks cached tip + `prev_digest` link; optionally re-verifies the full chain below trust on startup and every **32** pulls.

**vault.json:** `ic_vault_v`, `kdf_salt_b64` (16 bytes, same role as server `kdf_salt`), strict **`kdf`** (argon2id with minimum memory/iterations matching hosted vault), `wrapped_dek_b64` (wrapped DEK record with no extra JSON fields).

Implementation: `apps/js-sdk/lib/storage/layout.mjs`. Deterministic test vectors and tamper/rename/reorder tests: `apps/js-sdk/tests/storage/layout.test.mjs`. Fixed-nonce encryption is **test-only** (`apps/js-sdk/tests/helpers/layout-test-crypto.mjs`, not exported from `storage/index.mjs`). Vault unlock uses **`deriveVaultKekWithParams`** with the **`kdf`** block recorded in `vault.json` (bounded memory/iterations).
